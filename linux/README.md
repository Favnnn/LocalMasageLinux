# Мост на Linux — установка и запуск сервера

Сервер «Мост» — один файл, ничего устанавливать не нужно (Go, статический бинарник).
Есть сборки под две архитектуры:

| Файл | Архитектура | Типичные машины |
|---|---|---|
| `most-server-amd64` | x86_64 | обычные серверы и ПК, VPS |
| `most-server-arm64` | ARM64 | Raspberry Pi 4/5, Orange Pi, Ampere |

## Что в этой папке

```
linux/
├── most-server-amd64          сервер для x86_64
├── most-server-arm64          сервер для ARM64 (Raspberry Pi и т.п.)
├── install.sh                 установка + автозапуск + firewall + старт
├── uninstall.sh               удаление (данные чатов можно сохранить)
└── README.md                  эта инструкция
```

## Быстрая установка (рекомендуется)

1. Скопируйте **всю эту папку** на Linux-машину, например:

   ```bash
   # на Windows (PowerShell), заменив IP и пользователя:
   scp -r "C:\Users\Vad\Desktop\Проги DSH\Masage\linux" user@192.168.0.50:/tmp/
   ```

2. На Linux-машине:

   ```bash
   cd /tmp/linux
   sudo bash install.sh
   ```

   Скрипт сам: определит архитектуру, положит сервер в `/opt/most`,
   **пропишет автозапуск** (systemd, а без него — cron `@reboot`),
   откроет порт в firewall, если тот активен, и запустит сервер.

   Другой порт: `sudo bash install.sh 9000`

3. Увидите адреса — откройте на любом устройстве в сети:

   ```
   http://192.168.0.50:8410        ← адрес вашей Linux-машины
   ```

## Автозапуск после перезагрузки — как это устроено

- **Есть systemd** (Ubuntu, Debian, CentOS, Rocky…): создаётся служба `most`,
  включается в автозапуск, при падении перезапускается через 3 секунды.

  ```bash
  systemctl status most        # состояние
  journalctl -u most -f        # живые логи
  sudo systemctl restart most  # перезапуск
  ```

- **Нет systemd** (Alpine, докер-контейнеры, минималистичные системы):
  в `crontab` root добавляется строка

  ```
  @reboot /opt/most/most-server -port 8410 -data /opt/most/data -no-open >> /var/log/most.log 2>&1
  ```

  — при каждой загрузке сервер стартует сам, логи пишутся в `/var/log/most.log`.
  Это тот самый «крон», о котором вы спрашивали: вручную ничего прописывать не нужно,
  `install.sh` делает это сам.

## DevOps: сборка и доставка одной командой (с Windows-машины)

В папке проекта есть два скрипта автоматизации.

### 1. Сборка дистрибутива

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build-linux.ps1
```

Собирает оба бинарника, штампует версию (дата-время сборки UTC, например
`2026.11.12-1545`), пересобирает `most-server-linux.tar.gz`. Версия встроена в
бинарник — её видно в баннере при запуске, в `/api/info` и по флагу `-version`.

### 2. Доставка и развёртывание (scp → install.sh → проверка)

```powershell
# первый раз (адрес запомнится в deploy.json рядом с проектом):
powershell -NoProfile -ExecutionPolicy Bypass -File tools\deploy-linux.ps1 -Server user@192.168.0.50

# все следующие разы — просто:
powershell -NoProfile -ExecutionPolicy Bypass -File tools\deploy-linux.ps1
```

Конвейер: пересборка → копирование tar.gz на сервер → распаковка →
`install.sh` (sudo спросит пароль в этой же консоли) → **проверка, какая версия
теперь реально работает** (через `/api/info`) и статус службы.
Требуется включённый OpenSSH-клиент Windows (ssh/scp).

### Обновление до новой версии

Тот же деплой: новый бинарник копируется на сервер, служба `most`
**перезапускается скриптом установки** (не дожидаясь перезагрузки), версия
проверяется. Данные в `/opt/most/data` сохраняются. Убедиться, что работает
именно новая сборка:

```bash
curl -s http://127.0.0.1:8410/api/info | grep version
# или на сервере:
/opt/most/most-server -version
```

## Обновление вручную (если без DevOps-скриптов)

```bash
cd /tmp/linux                     # папка с новой версией
sudo bash install.sh              # перезапишет бинарник и перезапустит службу
```

Данные чатов в `/opt/most/data` **не трогаются** — история, файлы, комнаты,
пароли и владельцы сохраняются.

## Удаление

```bash
sudo bash uninstall.sh            # убрать программу (данные чатов останутся)
sudo bash uninstall.sh --purge    # убрать и данные тоже
```

## Запуск вручную (без установки)

```bash
./most-server-amd64                        # порт 8410, данные ./data
./most-server-amd64 -port 9000             # другой порт
./most-server-amd64 -data /var/lib/most    # своя папка данных
```

Флаги: `-port` (по умолчанию 8410), `-bind` (по умолчанию 0.0.0.0 — все сети,
включая VPN), `-data` (папка чатов), `-no-open` (не пытаться открыть браузер —
на сервере без графики это безопасно и так).

## Если что-то не открывается с другого устройства

1. `curl -s http://127.0.0.1:8410/api/info` — сервер отвечает? (значит, работает)
2. Порт открыт снаружи? `sudo ufw allow 8410/tcp` (Ubuntu) или
   `sudo firewall-cmd --permanent --add-port=8410/tcp && sudo firewall-cmd --reload`
3. Адрес машины: `ip addr | grep 'inet '`
4. Облачный сервер (VPS): откройте порт в панели провайдера (Security Group).

## Соответствие Windows-версии

Полностью: комнаты, пароли, скрытые комнаты, владельцы по устройству (uid),
кик/бан, история и файлы переживают перезапуск, тот же веб-интерфейс,
те же клиенты (Windows-EXE и APK просто вводят адрес Linux-сервера).
Формат данных (`data/rooms/...`) идентичен — папку `data` можно переносить
между Windows и Linux-серверами как есть.
